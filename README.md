# DNS Monitor

> 英文版：\[README.en.md](README.en.md)

本地运行的 Windows IPv4 DNS 监测工具。Go 后端、原生网页、SQLite 存储，使用同目录 DOGGO 发送 DNS 请求。无需安装运行时，无在线网页依赖。

## 人类的话

* 项目解决什么问题？本地DNS被污染/封锁->监控一批候选的DNS->在可达的DNS中由用户指定可信DNS，项目对比可信DNS，标记其它DNS是否受污染->输出数据结合adguard home搭建可信的DNS环境。
* 哪里获取DNS服务器？[jameshas/Public-DoH-Lists](https://github.com/jameshas/Public-DoH-Lists/) 或者 google 。

## 启动与移动

1. 解压 `dist/DNSMonitor-windows-amd64.zip`，或进入 `dist/DNSMonitor`。
2. 将 `doggo.exe` 放在 `dns-monitor.exe` 同目录下（见[安装 DOGGO](#安装-doggo)）。
3. 双击 `start.cmd`。网页默认地址 `http://127.0.0.1:8080`，默认监听 `0.0.0.0:8080`。
4. 首次运行会生成 `data/access-key.txt`。将里面的密钥粘贴至登录页；同一密钥用于本机和局域网访问。会话仅保存在浏览器内存中，刷新后重新登录，12 小时过期。
5. 添加服务器与供应商；在服务器表单勾选你认可的可信 DNS；配置域名后开始监测。

数据与配置保存在 `data/monitor.db`，滚动日志在 `logs`。退出程序后复制**整个文件夹**即可迁移（需包含 `doggo.exe`）。备份前也应先正常停止；运行期间 SQLite 可能同时使用 `.db-wal`、`.db-shm`。不要只复制正在使用的 `.db`。

升级前退出旧程序并备份 `data`，替换程序和随包文件后启动。v1.2 会自动升级数据库，可信历史随数据目录一起迁移；需要回退旧版时使用升级前的数据备份。

仅面向 Windows 10/11、Windows Server 2016 及以上的 amd64 系统与 IPv4 传输。不创建 Windows 防火墙例外。局域网是否可访问取决于现有防火墙配置；默认 HTTP 适用于可信本地网络，跨不可信网络应通过已有 HTTPS 反向代理或 VPN。

## 监测与统计

* 监测服务器的可达情况、平均与 P95 时延、查询成功率；按协议、供应商、污染状态、评级筛选，默认按当前评级排序，也可按时延排序。
* 支持 24 小时、7 日、30 日视图。原始探测记录、回答、可信源证据保留滚动 30 天，程序启动及每小时清理超期数据。清理后 SQLite 文件空间可复用，不保证文件立即变小。
* 收到 DNS 响应代表可达；NOERROR 且有相应记录、或明确的 NXDOMAIN 负回答代表查询成功。无可识别响应码的空回答不计成功。记录不使用 ICMP，不把 DNS 超时称为实际网络丢包率。
* 可用率按已观察时间加权；查询成功率按实际查询次数计算。失败退避期间不会凭空生成成功记录；停止运行后的未覆盖时间保留为空档。覆盖率帮助区分“尚未监测”与“服务故障”。
* 时延使用 DOGGO 提供的查询耗时；P95 使用向上取整至 1ms 的直方图统计，误差不超过 1ms。趋势图使用聚合数据；原始记录支持 CSV 导出。

## 探测配置

默认周期 300 秒、超时 3 秒、并发 2。并发范围 **0–50**，**0 表示暂停所有新探测**，包括手动触发。已有请求会在超时界限内结束。

智能惩罚对连续失败的服务器逐步延长周期，最大退避 **0–24 小时**，默认 **1 小时**。**0 表示关闭退避**。退避上限不低于基础周期，调度加入 0–10% 的负向抖动，最短不低于 5 秒。错峰、抖动、有界任务队列和同服务器不重叠机制限制瞬时负载。长时间离线后首次恢复会在约 30 秒内复核，然后回归基础周期。更改监听地址需重启生效，其余配置热生效。

新建配置默认探测 **www.youtube.com / A**。已有配置继续使用已保存的域名，支持自行增删多个探测域名和记录类型。仅 IPv4 限制的是访问 DNS 的网络传输与服务器地址。域名应填写 ASCII/Punycode，不接受 URL；不支持 IPv6 上游。

地址使用 AdGuard Home 常用上游写法，例如：

```text
1.1.1.1
8.8.8.8:53
udp://9.9.9.9:53
tcp://1.1.1.1
tls://dns.google
https://cloudflare-dns.com/dns-query
h3://dns.google/dns-query
quic://dns.adguard-dns.com
sdns://...
```

DNS stamp 支持普通 UDP、IPv4 DNSCrypt，以及不附带固定 IP、证书 hash 和 bootstrap 约束的 DoH/DoT/DoQ。随包 DOGGO 不能正确保留这些加密 stamp 约束，遇到它们会明确拒绝，建议填写对应标准上游 URL。AdGuard Home 的分域路由指令（如 `\[/example.com/]...`）、特殊 `#` 系统默认上游和不安全 TLS 选项不属于单台被测服务器地址，保存时会明确拒绝。域名上游启动解析依赖主机可用的 IPv4 DNS；本项目不修改系统 DNS。探测隔离继承的 DOGGO 配置和 HTTP(S) 代理环境变量，直接测量 DNS 访问路径。加密协议额外绑定 IPv4 来源，保留 TLS 证书校验。

## 可信参考与四档判定

在服务器管理中，由用户指定可信 DNS。系统只对同一域名、A 记录的 IPv4 回答建立参考池，不混用不同域名，也不让普通被测服务器扩充可信参考。

* **新鲜参考**：可信 DNS 实际返回且 TTL 尚未过期的地址；遇到 CNAME 解析链时采用链路与 A 记录中的较短 TTL。TTL 最大按 24 小时处理，缺失、无效或零 TTL 不作为新鲜参考。
* **近期历史**：可信 DNS 最近实际返回过的地址，默认保留 **1 小时**，可配置 **0–720 小时**，支持小数；0 关闭历史参考。期限从最后一次实际观察计算，失败查询与读取缓存不会延长历史。TTL 尚有效的记录仍可作为新鲜参考。
* 参考池持久化，重启后继续使用有效记录。取消可信、禁用或更改来源地址会清除该来源的参考；再次启用或信任需重新采集。每个来源/域名/类型最多 256 个地址，全局最多 16384 个，达到上限按最近观察时间淘汰。

每个返回 IP 独立比对，一次回答取最差档：

|解析状态|判断依据|综合评级|
|-|-|-|
|参考一致|所有 IP 命中新鲜参考|按性能评 A–D 或待评估|
|正常|全部命中新鲜或有效历史，部分仅命中历史|按性能评 A–D 或待评估|
|可疑|存在未见过的 IP，但这些 IP 均能匹配参考池中的 IPv4 前两段（/16）|E|
|疑似污染|至少一个 IP 未命中参考池，且前两段也不匹配|F|

前缀集合来自新鲜参考与仍在保留期内的历史。相同前缀不保证安全，不同前缀也可能是正常 CDN 调度；E/F 是自动规则分级，不能视为独立验证了污染。没有可用参考、无可比较 IPv4 或查询失败时显示待判定，不按空集合定罪。非 A 查询仍可监测可用性与时延，但不套用 IPv4 前缀规则。

每次判定直接使用现有有效的新鲜参考与历史集合，**不要求所有可信 DNS 都已返回或参考都未过期**。某个来源离线、超时或参考失效，不会阻止使用其他来源的有效地址评定四档结果；准备评 E/F 时也不再强制补查。可信 DNS 的正常周期探测会持续扩充集合。

仅在没有任何有效参考时才尝试补采，取得首个可用参考即可判断；同域名共享采集，空池重试最短间隔 30 秒。可信查询缓存默认上限 300 秒，同时受实际 TTL 限制；TTL 到期不会主动高频发包。全部查询仍受全局并发上限约束。手动刷新要求新的实际探测，保留可信历史。

**用户指定可信服务器永远不评 E/F**，解析质量显示“用户可信 / 无污染”，性能仍按 A–D 或待评估显示。其他服务器可点击域名人工确认污染、取消污染或恢复自动判定；人工决定持续作用于该服务器、域名和记录类型。人工确认显示已确认污染，取消污染显示正常，原始自动结果与证据保留。

从旧版本升级时，旧算法产生的自动 F 仅保留原始证据，有效状态改为待判定，不继续影响新版本 E/F 评级；历史人工判定保留。

总览的**当前解析质量**取评级窗口内最新正式轮次；窗口内没有采样时，非可信 DNS 显示待判定，优先级为 F、E、待判定、正常、参考一致。一轮内若有 A 查询待判定，不会被同轮另一个正常答案掩盖；非 A 查询的自动待判定不影响同轮 A 查询。历史中的正常或 E/F 不再阻止当前状态更新。只有辅助可信查询发生变化时，不更新被监测服务器的当前状态。

**当前评级**默认只观察最近 **60 分钟**，至少需要 **3 次正式采样、5 分钟有效覆盖**。默认单域名、5 分钟周期通常约 10 分钟形成评级。三项可在“探测配置 → 当前状态与评级”调整：观察窗口 5–1440 分钟、最少采样 1–100 次、最小覆盖 0–1440 分钟且不能超过观察窗口；最小覆盖为 0 时不额外等待覆盖时长。手动刷新可增加真实采样，不会凭空增加已覆盖时长。修改参数直接对现存证据重新计算，无需清空数据。

最新一轮正式探测全部查询失败（连接失败、超时或解析错误）时，当前评级立即显示**不可用**，当前评分为 0，优先于污染评级及样本门槛；可信标记不豁免。最新一轮有成功查询后重新按正常规则评级，窗口内无正式采样仍为待评估。历史指标不受影响。

当前 F/E 优先于样本门槛；非可信服务器当前解析质量待判定时，当前综合评级也显示待评估，悬停说明原因、采样及覆盖进度。待判定不代表已污染：可能是查询失败、没有可比较的 A 记录，或可信参考不足。性能指标和近期性能评分仍保留，当前汇总 CSV 可导出。可信服务器豁免 E/F 和解析待判定对评级的影响，仍需满足性能采样门槛。

其余按可用率 45%、查询成功率 35%、P95 时延 20% 评分得到 A–D（A ≥95，B ≥85，C ≥70，其余 D）。P95 ≤50ms 获得满额时延分，≥2000ms 为零，中间线性递减。当前窗口没有正式采样时回到待评估；长期离线退避可能导致近期样本不足，可在保留证据门槛的前提下调整观察窗口。

表格的时延、可用率、成功率及详情图表继续按所选 **24 小时／7 日／30 日**统计。历史聚合指标保留区间内最严重的已知解析结果及原有 10 次采样／30 分钟历史评分门槛；它们与当前状态分开计算、返回。切换历史区间不会改变当前评级。原始探测证据与手工判定不被重写。

DOGGO 的 `--do`、`--ad` 与权威查询不足以自行证明 DNSSEC 完整签名链已验证，本版不依据这些标志自动创建系统可信 DNS。

## 手动刷新、排序与 CSV

* 总览顶部“刷新”会立即安排所有已启用 DNS 的新一轮实际探测，清除本轮可信参考缓存，并显示进度；受并发上限约束，正在探测的节点会在当前轮后追加一轮。连续点击合并到正在进行的批次。自动刷新页面只读取结果，不额外发起探测。
* 并发为 0 时暂停探测；刷新过程中暂停会结束本次刷新跟踪并说明未完成。恢复后可重新刷新。
* 默认按当前评级 A、B、C、D、E、F 排序，也支持反向或手动切换排序；待评估位于字母评级之后；不可用在所有排序方式及方向中始终置底。
* 总览表格右上方“导出当前结果”导出当前时间范围、筛选与排序下的监测汇总，包含所选区间性能指标、当前解析质量和评级、评级窗口、评级采样及等待原因。服务器详情的“导出原始记录”提供逐次探测证据；使用指南中的原始记录入口可导出全部节点。
* “服务器清单”区域的 CSV 导入/导出只处理服务器配置，与监测结果分开。导入窗口可下载 UTF-8 CSV 模板，字段为 `name,provider,address,enabled,trusted,notes`。名称与地址必填，地址决定协议。
* 按规范化 DNS 地址检查重复，包括默认端口和支持的 DNS stamp 等价写法。预览后逐条选择跳过/覆盖，也可勾选全部跳过/全部覆盖；CSV 文件内部的重复也会显示。不同协议、非默认端口或 DoH 路径仍视为不同地址。
* 覆盖保留现有服务器 ID 和监测历史；没有提供的可选列保留原值，显式提供的列应用导入值。新节点默认启用、默认不可信。导入一次性提交，预览后若清单发生变化会要求重新预览，不会部分写入。
* 每次最多 1000 条、900 KiB；无效行必须修正后提交。已有清单如存在多个同地址节点，需先整理歧义再导入。导出文本以防止电子表格公式执行的方式转义。

界面采用系统字体，参考 [Apple Typography 指引](https://developer.apple.com/design/human-interface-guidelines/typography) 的字号层级、字重、对比度与留白原则，并适配浏览器缩放；不依赖外部字体下载。

## Windows 服务

网页“Windows 服务”页与 `manage-service.cmd` 提供安装、卸载、启动、停止、重启、状态查询。管理时使用 Windows 原生管理员授权，安装不会自动启动，也不会自动改动防火墙。

服务名 `DNSMonitor`，延迟自动启动，使用 Windows 默认 LocalSystem 服务账户。要切换到服务运行，请先安装，然后正常退出当前便携进程，再通过 `manage-service.cmd` 启动服务，避免端口和数据文件被两个实例占用。服务运行时也可以访问相同网页。管理结果写入 `logs/service-action.log`。

**移动目录前先停止并卸载服务，移动后重新安装**；服务注册了绝对路径。普通便携运行不需要服务。

## 开发与构建

Go 1.24+，Windows amd64。无需 Node.js 或 C 编译器；SQLite 使用 Go 驱动。需要外部程序 DOGGO 用于 DNS 探测。首次构建需要联网下载 Go 模块。

### 安装 DOGGO

DOGGO 是独立的 DNS 客户端工具，需自行安装。推荐将 `doggo.exe` 放在 `dns-monitor.exe` 同目录下：

```powershell
# 方法一：下载后放入程序目录
# 从 https://github.com/mr-karan/doggo/releases 下载 windows-amd64 版本，解压后将 doggo.exe 放在 dns-monitor.exe 旁

# 方法二：安装到 PATH
scoop install doggo
# 或
go install github.com/mr-karan/doggo/cmd/doggo@latest
```

程序启动时按以下顺序查找 doggo：① `--doggo` 参数指定路径 → ② 程序同目录 `doggo.exe` → ③ PATH 环境变量。均未找到时给出安装指引。

```powershell
.\\build.ps1
```

构建脚本执行测试和 `go vet`，生成便携目录与 ZIP，并收集第三方许可证。工具链如不在 PATH，可放入 `.tools/go`。`.tools`、`data`、`logs`、`dist` 均不进入 Git。

主要代码：`cmd/dns-monitor` 启动与生命周期，`internal/httpapi` 接口与会话，`internal/monitor` 探测调度，`internal/store` 存储与统计，`internal/web` 网页，`internal/winservice` Windows SCM 管理。

CPU 和内存开销随服务器数量、周期、并发、协议变化。默认并发 2，每次只启动有界数量 DOGGO 子进程；图表查询聚合历史并短暂缓存，日志限量滚动。批量探测量约为 `服务器数 × 域名数 × 86400 / 周期秒数` 次/日，另加无有效参考时的有界可信源补采。原始证据保留意味着磁盘用量随探测量增长。为限制异常子进程输出，每次 DOGGO 的 stdout/stderr 各最多保留 256 KiB；超限记录错误，不用于污染比对。

DOGGO 是独立外部程序，许可证见 https://github.com/mr-karan/doggo ；本项目许可证见 `LICENSE`。其他依赖许可证见发行包 `licenses`。

## 解析质量与评级历史

* 服务器清单在当前解析质量和当前评级下显示历史色块；点击任一色块条可打开 SERVER INSIGHTS。
* 清单与详情均支持 24 小时、7 天、30 天，分别以 30 分钟、3 小时、12 小时为一格。每格取其中最差的已记录状态，短暂异常不会被平均值掩盖；这不代表整个时段都处于该状态。
* 详情同时展示两条对齐的时间轴。悬停、键盘聚焦或点击色块，可查看各状态的探测次数，以及该格末次快照的评级、观察窗口、采样数、查询成功率和平均时延。
* 正式探测完成时保存当时的解析质量、评级及其指标和阈值；可信参考的辅助查询不产生评级快照。后续修改评级配置、可信标记或人工判定不会重写已保存的快照，新的设置在下一轮正式探测快照中体现。
* 升级前未保存快照、停止探测或没有正式探测记录的时间格显示灰色斜纹“无数据”，不会使用当前评级回填。“待判定 / 待评估”和“不可用”有独立颜色。
